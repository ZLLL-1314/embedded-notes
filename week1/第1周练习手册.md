## Day 1（10/12 周一）环境搭建 + 数据类型与运算符

**目标**：能自己建一个三文件工程并编译、能说清基本类型的字节数和溢出陷阱。

### 练习
1. **三文件工程**：`main.c` + `calc.h` + `calc.c`，实现 `add` `sub` `mul` 和 `int sdiv(int a, int b, int *rem)`（返回商，余数通过指针带出）。
2. **类型探针**：打印 `char/short/int/long/long long/float/double/指针` 的 `sizeof`，并在注释里写出你机器上每个类型是 32 位还是 64 位。
3. **成绩分档**：输入一个整数分数，输出等级：`90-100 → A`，`80-89 → B`，`70-79 → C`，`60-69 → D`，`0-59 → F`，其他 → `非法`。

### 测试数据（练习 3）
| 输入 | 期望输出 |
|---|---|
| 95 | A |
| 90 | A |
| 89 | B |
| 75 | C |
| 60 | D |
| 59 | F |
| 0 | F |
| -1 | 非法 |
| 101 | 非法 |

### 测试数据（练习 1）
| 调用 | 期望 |
|---|---|
| `sdiv(7, 2, &r)` | 返回 3，r = 1 |
| `sdiv(-7, 2, &r)` | 返回 -3，r = -1（C99 截断除法） |
| `sdiv(5, 0, &r)` | 不崩溃、不打印垃圾值，走错误分支 |

### 验收清单
- [ ] `gcc -Wall -Wextra main.c calc.c -o calc` 零警告零错误
- [ ] 9 条成绩用例全部正确
- [ ] 除数为 0 时程序不崩溃（你会怎么设计错误处理？用返回错误码还是打印并返回？在注释里写清你的选择和理由）

### 卡住时的提示
- `long` 在 Windows（LLP64）是 4 字节，在 Linux（LP64）是 8 字节，这个差异后面端口相关会踩到
- 除零在 C 里是未定义行为，`sdiv` 应该**在调用前检查** `b == 0` 并返回错误码，而不是让它算下去

## Day 2（10/13 周二）指针

**目标**：指针不再是"看得懂但写不出"，能画出指针变化追踪表。

### 练习
1. 写 `void swap(int *a, int *b)`，并写测试证明两个变量真的被交换了。
2. 给定 `int a[5] = {1,2,3,4,5};` **只用指针**（不许用下标）实现：求和、求最大值、原地逆序。
3. **表达式追踪表**：对同一段代码 `int a[5] = {1,2,3,4,5}; int *p = a;` 分别单独运行下面 5 个表达式，填出结果表：`*p++`、`(*p)++`、`++*p`、`*++p`、`++(*p)`。
4. **二进制打印**（为 Day5 铺垫）：`void print_bin8(unsigned char x)` 打印 8 位二进制，高位在左。

### 测试数据（练习 2）
输入数组 `{1,2,3,4,5}` → 期望 `sum = 15`、`max = 5`、逆序后 `5 4 3 2 1`。

### 测试数据（练习 3）— 每行单独跑一次，填表
| 表达式 | 输出值 | 执行后 p 指向 | 执行后数组内容 |
|---|---|---|---|
| `*p++` | 1 | a[1] | 1 2 3 4 5 |
| `(*p)++` | 1 | a[0] | 2 2 3 4 5 |
| `++*p` | 2 | a[0] | 2 2 3 4 5 |
| `*++p` | 2 | a[1] | 1 2 3 4 5 |
| `++(*p)` | 2 | a[0] | 2 2 3 4 5 |

> 先把表遮住自己做一遍，再对照。做错的每一行都要在笔记里写清"为什么会这样"。

### 测试数据（练习 4）
| x | 期望输出 |
|---|---|
| 0xA5 | 10100101 |
| 0x00 | 00000000 |
| 0xFF | 11111111 |
| 0x01 | 00000001 |

### 验收清单
- [ ] 5 行追踪表全部与上表一致，且能口头解释每一行
- [ ] 能回答"二级指针 `int **pp` 什么时候用"（提示：想改一个指针本身，或者二维数组传参）
- [ ] 能回答"数组名和指针到底差在哪"（`sizeof`、`&arr` 的类型、传参退化）

### 卡住时的提示
- 记住优先级：后缀 `++` > 前缀 `++` > 解引用 `*`
- 分不清就把代码拆成两步写（`int v = *p; p++;`）再对照，看拆完是不是和一行版本结果一样

## Day 3（10/14 周三）字符串与内存

**目标**：能手写标准库字符串函数，并讲清它们为什么不安全。

### 练习（全部手写，不许调用标准库）

2. `char *my_strcpy(char *dst, const char *src)`
3. `int my_strcmp(const char *a, const char *b)`
4. `void *my_memcpy(void *dst, const void *src, size_t n)`
5. `void *my_memmove(void *dst, const void *src, size_t n)`（必须处理内存重叠）
6. `void *my_memset(void *dst, int c, size_t n)`

### 测试数据
| 调用 | 期望 |
|---|---|
| `my_strlen("")` | 0 |
| `my_strlen("abc")` | 3 |
| `my_strlen("你好")` | 6（UTF-8 下每个汉字 3 字节，加分题） |

- [ ] `my_strlen` 的返回类型为什么是 `size_t` 而不是 `int`？如果 `s == NULL` 会怎样？

### 验收清单

## Day 4（10/15 周四）结构体、联合体、内存对齐

**目标**：搞懂结构体大小为什么"不等于成员之和"，这是协议打包和面试必考。

### 练习
1. 定义 `typedef struct { unsigned char id; unsigned short value; float temp; } Sensor_t;` 打印它的 `sizeof`，并用 `offsetof` 打印每个成员的偏移，画图解释空隙在哪。
2. 给同一个结构体加 `#pragma pack(1)`（或 `__attribute__((packed))`），再打印 `sizeof`，对比差异并写注释说明"协议打包为什么要这么干"。
3. 用 `union` 写一个 `is_little_endian()` 判断大小端。
4. 结构体数组操作：定义 5 个 `Sensor_t`，**用结构体指针 + `->`** 遍历，按 `value` 从小到大冒泡排序后打印。

### 测试数据（练习 1、2）
| 场景 | 期望 sizeof（gcc/x86_64 或 MinGW） |
|---|---|
| 默认对齐 | 12 |
| pack(1) | 7 |

成员偏移（默认对齐）：`id → 0`、`value → 2`、`temp → 4`。

> 为什么是 12 不是 7？把你的推理写在笔记里：每个成员要放在自身对齐数的整数倍偏移上；结构体总大小要补齐到最大成员对齐数的整数倍。

### 测试数据（练习 3）
小端机器上 `is_little_endian()` 返回 1（x86 和 STM32 都是小端）。

### 测试数据（练习 4）
输入 `{{1,30,25.5}, {2,10,26.0}, {3,50,24.1}, {4,20,23.8}, {5,40,27.2}}`
按 value 升序输出 id 顺序：`2 4 1 5 3`

### 验收清单
- [ ] sizeof 和 offsetof 实测结果与上表一致，能解释每个字节的来历
- [ ] 能说出 packed 的代价（成员地址不再对齐，某些 ARM 平台访问会异常）
- [ ] 排序结果正确，且遍历用的是指针不是下标

### 卡住时的提示
- 画一张 12 格的格子表，从偏移 0 开始一个个填，空格就是 padding
- `offsetof` 需要 `#include <stddef.h>`

## Day 5（10/16 周五）位运算与"软件模拟寄存器"

**目标**：这是本周最重要的一天。STM32 所有外设配置本质上都是今天这套操作。

### 练习
1. **位操作宏**：写 `BIT_SET(x,n)` `BIT_CLR(x,n)` `BIT_TOGGLE(x,n)` `BIT_GET(x,n)`（用移位和掩码，不要一行塞太多逻辑），并写测试。
2. **模拟 GPIO 寄存器**（用一个真实结构体当寄存器组）：
```c
typedef struct { uint32_t MODER; uint32_t ODR; uint32_t IDR; } GPIO_Reg_t;
```
   规则：`MODER` 每个引脚占 2 位（00 输入 / 01 输出 / 10 复用 / 11 模拟），`ODR` 每引脚 1 位输出电平，`IDR` 每引脚 1 位输入电平。实现：
   - `void gpio_set_mode(GPIO_Reg_t *g, int pin, uint32_t mode);`
   - `void gpio_write_pin(GPIO_Reg_t *g, int pin, int level);`
   - `void gpio_toggle_pin(GPIO_Reg_t *g, int pin);`
   - `int gpio_read_pin(GPIO_Reg_t *g, int pin);`
   - `void reg_dump(const GPIO_Reg_t *g);` 打印三个寄存器的 16 进制和 32 位二进制
3. **顺手练两个经典位运算题**：`uint8_t reverse_bits(uint8_t x)` 和 `int count_ones(uint32_t x)`。

### 测试数据（练习 2）— 操作序列与期望值
寄存器初始化为 0，按顺序执行：

| 步骤 | 操作 | 期望 MODER | 期望 ODR | 期望返回值 |
|---|---|---|---|---|
| 1 | `set_mode(pin 3, 2)` | 0x00000080 | 0 | — |
| 2 | `set_mode(pin 0, 1)` | 0x00000081 | 0 | — |
| 3 | `write_pin(3, 1)` | 0x00000081 | 0x00000008 | — |
| 4 | `read_pin(3)` | — | — | 1 |
| 5 | `toggle_pin(3)` | — | 0x00000000 | — |
| 6 | `write_pin(5, 1)` | — | 0x00000020 | — |

> 第 3 步的 `0x08`：ODR 第 3 位置 1 就是 `1 << 3`。第 1 步的 `0x80`：MODER 第 3 号引脚占 bit7:bit6，写 2 就是 `10` → `0x80`。
> **必须能解释这两行，能解释就等于懂了 STM32 的 GPIO 配置**。

### 测试数据（练习 3）
| 调用 | 期望 |
|---|---|
| `reverse_bits(0xB1)`（10110001） | 0x8D（10001101） |
| `reverse_bits(0x00)` | 0x00 |
| `reverse_bits(0xFF)` | 0xFF |
| `count_ones(0xA5)` | 4 |
| `count_ones(0xFFFFFFFF)` | 32 |
| `count_ones(0x00)` | 0 |

### 验收清单
- [ ] 操作序列表 6 步全部对得上
- [ ] `write_pin(pin, level)` 里不能用 `if/else` 分支写死，要用"读改写"三步（清位 → 置位）
- [ ] 能回答：为什么嵌入式里寄存器指针必须加 `volatile`？（提示：编译器优化会认为该变量没人改过）

### 卡住时的提示
- `set_mode` 三步走：读出 MODER → 清掉那 2 位（`&= ~(3 << (pin*2))`）→ 与上 mode（`|= (mode & 3) << (pin*2)`）
- 写位时不要直接 `|= 1 << pin`，那样置 0 会失效，要先清后置

## Day 6（10/17 周六）函数指针、回调、状态机分词

**目标**：会写"表驱动"代码，且做出 Day7 要用的分词器。

### 练习
1. **回调表分发**：定义
```c
typedef void (*cmd_fn_t)(const char *args);
typedef struct { const char *name; cmd_fn_t fn; } CmdEntry_t;
```
   建一张命令表（help / set / get），写 `void dispatch(const char *cmd, const char *args)`：查表命中就调用对应函数，未命中调用 `default_handler` 打印 `unknown: xxx`。
2. **状态机分词器**（Day7 的核心零件）：
```c
int tokenize(const char *line, char tokens[][32], int max_tokens);
```
   把一行按空格/Tab 切成多个 token，返回 token 个数；连续空格只算一个分隔符；行首行尾的空白忽略。
3. **static 作用域实验**：把 Day5 的代码拆成 `gpio.h` / `gpio.c`，把 `reg_dump` 改成 `static`，观察 `main.c` 里调用它会发生什么，并把报错信息记进笔记。

### 测试数据（练习 1）
命令序列 `help` → `set a 1` → `get a` → `bogus` → `help`，期望输出依次为：
```
help called
set called: a 1
get called: a
unknown: bogus
help called
```

### 测试数据（练习 2）
| 输入行 | 期望 token 个数 | 期望 token 内容 |
|---|---|---|
| `set a 1` | 3 | `set` `a` `1` |
| `  set   a\t1 ` | 3 | `set` `a` `1` |
| `get a` | 2 | `get` `a` |
| `""`（空行） | 0 | — |
| `"   "`（只有空格） | 0 | — |
| `help` | 1 | `help` |

### 验收清单
- [ ] 触发未注册命令时不会崩溃，走默认分支
- [ ] 分词器能正确处理连续空格、tab、行首行尾空白（这是 Day7 最容易扣分的地方）
- [ ] 记录了 static 函数跨文件调用的具体报错信息，并能解释原因

### 卡住时的提示
- 分词用状态机思路：两个状态 `IN_SPACE` / `IN_WORD`，遇空格结束当前 token
- 回调表用 `for` 循环 + `strcmp` 遍历匹配，命中后 `break`

## Day 7（10/18 周日）综合小项目：串口命令行式的 key-value 命令解析器

**目标**：把前六天的东西拼成一个能写进简历雏形的完整程序。

### 功能需求
1. 从标准输入逐行读取命令（`fgets`），每读一行处理一次
2. 支持命令：
   - `help` → 打印一行命令说明
   - `set <key> <value>` → 写入/覆盖键值对
   - `get <key>` → 打印该键的值
   - `del <key>` → 删除键
   - `list` → 按**插入顺序**打印所有键值对
   - `quit` → 打印 `BYE` 并退出（返回码 0）
3. 数据存储：固定容量 16 条的表；key 最长 16 字符；value 为 `int`（支持负数）
4. 必须复用 Day6 的 `tokenize()`，并拆成至少 3 个文件
5. 空行（或全空白行）不产生任何输出

### 错误处理规则（输出必须**逐字**一致）
| 情况 | 输出 |
|---|---|
| 未知命令 | `ERR: unknown command` |
| `set`/`get`/`del` 参数个数不对 | `ERR: bad args` |
| value 不是合法整数 | `ERR: bad value` |
| key 长度超过 16 | `ERR: key too long` |
| 表已满且要新增键 | `ERR: full` |
| key 不存在（get/del） | `ERR: not found` |
| 正常执行 | `OK` |
| `help` | `commands: help | set <k> <v> | get <k> | del <k> | list | quit` |
| `list` | `list: k1=v1 k2=v2 ...`（无数据时输出 `list:` ） |
| `quit` | `BYE` |

**输出要求**：不可以打印提示符（如 `> `），不可有多余空行，否则对拍通不过。

### 对拍方式（重点）
同目录下已经给你两个文件：`day7_input.txt` 和 `day7_expected.txt`。

Windows（PowerShell）：
```
.\parser.exe < day7_input.txt > my_out.txt
fc.exe my_out.txt day7_expected.txt
# 若出现换行符（CRLF/LF）差异的误报，用这个更稳的比法（按行比较，忽略行尾差异）：
Compare-Object (Get-Content my_out.txt) (Get-Content day7_expected.txt)
```
Linux / WSL：
```
./parser < day7_input.txt > my_out.txt
diff my_out.txt day7_expected.txt
```
**没有任何差异输出 = 通过。** 这就是嵌入式行业里"写测试工具脚本做自动验证"的最小版本，也正是乐鑫 JD 里那条"开发与优化测试工具脚本"。

### 附加测试（手工做，不放进对拍文件）
- **表满**：连发 17 条 `set k1 1` … `set k17 17`，第 17 条应输出 `ERR: full`
- **重复删除**：`del a` 两次，第二次应为 `ERR: not found`
- **CRLF**：如果你在 Windows 上用文本编辑器存输入文件，行尾会带 `\r`，测试你的解析器能否容忍（提示：把行尾的 `\r` 和 `\n` 都替换成 `\0`）
- **超长输入行**：输入 200 个字符的行，程序不能越界崩溃

### 验收清单
- [ ] `fc`/`diff` 无差异
- [ ] 4 项附加测试通过
- [ ] 分成 ≥ 3 个源文件（例如 `main.c` / `kv.c` / `tokenize.c` + 对应 `.h`）
- [ ] `-Wall -Wextra` 零警告
- [ ] README 写清：数据结构、分词思路、遇到的一个 bug 及定位过程
- [ ] `git log` 本周至少 7 次提交
- [ ] 写完后发我，我会按面试标准挑问题（命名、边界、内存安全、设计取舍）

### 卡住时的提示
- 别想一次写对。顺序是：先让 `quit`/`help` 跑通 → 再加 `set/get` → 再加 `del/list` → 最后补错误分支
- `value` 用 `strtol` 解析，检查 `endptr == '\0'` 才是"整个字符串都是数字"
- `list` 要按插入顺序，最简单的做法就是数组按插入顺序存，删除时后面元素前移
